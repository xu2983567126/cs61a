问题 3

实现 accuracy，它同时接受一个 entered 段落和一个 source 段落。它返回 entered 中与 source 中对应单词完全匹配的单词所占的百分比。大小写和标点符号也必须匹配。“对应”的意思是：entered 中的每个单词必须出现在 source 中与之匹配的单词的相同位置上。换句话说，entered 中的第一个单词必须匹配 source 中的第一个单词，entered 中的第二个单词必须匹配 source 中的第二个单词，依此类推。

在本文语境下，一个单词是指由空白字符与其他单词分隔开的任意字符序列。因此，像 "dog;" 这样的序列应被视为一个单词。

在真正的打字测试中，entered 表示玩家已经输入的内容，而 source 是他们试图复现的段落。

  • 如果 entered 比 source 长，那么 entered 中那些在 source 里没有对应单词的多余单词都视为不正确。
  • 如果 entered 比 source 短，且 entered 中的所有单词目前都与 source 对应，那么准确率为 100.0。
  • 如果 entered 为空且 source 也为空，那么准确率为 100.0。
  • 如果 entered 为空但 source 不为空，那么准确率为 0.0。
  • 如果 entered 不为空但 source 为空，那么准确率为 0.0。

问题 4

实现 wpm，它根据输入的字符串 entered 以及经过的 elapsed 时间（单位为秒），计算出“每分钟字数”（words per minute），即一种打字速度的度量。尽管名字如此，“每分钟字数”并不是基于实际输入的单词数量，而是基于每 5 个字符为一组的数量，这样打字测试就不会因单词长度而存在偏差。“每分钟字数”的计算公式为：将输入的总字符数（含空格）除以 5（平均单词长度），再将结果除以经过的时间（单位为分钟）。

例如，字符串 "I am glad!" 包含十个字符（不含引号）。每分钟字数的计算将 2 视为输入的单词数（因为 10 / 5 = 2）。如果有人在 30 秒（半分钟）内输入了这个字符串，那么他的速度就是每分钟 4 个字。

阶段 2：自动纠错

在网页版 GUI 中，有一个“启用自动纠错”（Enable Auto-Correct）选项，但目前它没有任何作用。让我们来实现自动纠错功能。每当用户按下空格键时，如果他们输入的最后一个单词与字典中的单词不匹配，但又与之接近，那么那个相似的单词就会替换他们所输入的内容。

问题 5

实现 autocorrect，它接受 entered_word、word_list、diff_function 和 limit。autocorrect 的目标是返回 word_list 中由 diff_function 判定为与所给 entered_word 最接近的那个单词。

具体来说，autocorrect 会执行以下操作：

  • 如果 entered_word 包含在 word_list 中，autocorrect 就返回该单词。
  • 否则，autocorrect 返回 word_list 中与所给 entered_word 差异最小的单词。这个差异就是 diff_function 返回的数值。
  • 不过，如果 entered_word 与 word_list 中任意单词的最小差异大于 limit，那么就改为返回 entered_word。换句话说，limit 设定了一个最大阈值，只有错误程度不超过它时才会被纠正。

假设 entered_word 以及 word_list 中的所有元素都是小写字母，且不含标点符号。

重要： 如果 word_list 中有多个字符串与 entered_word 的差异并列最小，autocorrect 应返回在 word_list 中出现最早（索引最小）的那个字符串。

diff 函数接受三个参数。第一个是 entered_word，第二个是源单词（在这里即 word_list 中的一个单词），第三个参数是 limit。diff 函数的输出是一个数字，表示两个字符串之间的差异程度。

下面是一个 diff 函数的例子，它计算 1 + limit 与两个输入字符串长度之差中的较小值：

>>> def length_diff(w1, w2, limit):
...     return min(limit + 1, abs(len(w2) - len(w1)))
>>> length_diff('mellow', 'cello', 10)
1
>>> length_diff('hippo', 'hippopotamus', 5)
6

注意： 为了简洁，一些解锁测试在定义 lambda 函数时会使用三元运算符。三元运算符就是 if 语句的单行版本。

例如，在其中一个 ok 测试中，我们将 diff 函数定义为 first_diff = lambda w1, w2, limit: 1 if w1[0] != w2[0] else 0。这里，如果 w1 和 w2 的首字符不同，lambda 函数返回 1，否则返回 0。

问题 6

实现 furry_fixes，它是一个可以作为 diff_function 参数传给 autocorrect 的 diff 函数。这个函数接受两个字符串，并返回为了把 entered 单词转换成 source 单词而必须修改的最少字符数。如果两个字符串长度不相等，则长度之差会被计入总的修改次数。

下面是一些例子：

>>> big_limit = 10
>>> furry_fixes("nice", "rice", big_limit)    # Substitute: n -> r
1
>>> furry_fixes("range", "rungs", big_limit)  # Substitute: a -> u, e -> s
2
>>> furry_fixes("pill", "pillage", big_limit) # Don't substitute anything, length difference of 3.
3
>>> furry_fixes("goodbye", "good", big_limit) # Don't substitute anything, length difference of 3.
3
>>> furry_fixes("roses", "arose", big_limit)  # Substitute: r -> a, o -> r, s -> o, e -> s, s -> e
5
>>> furry_fixes("rose", "hello", big_limit)   # Substitute: r->h, o->e, s->l, e->l, length difference of 1.
5

重要： 你的实现中不得使用 while、for 或列表推导式。请使用递归。

如果要修改的字符数大于 limit，那么 furry_fixes 应该返回一个大于 limit 的任意数字，并且应当尽量减少为此所需的计算量。

阶段 4：效率（额外挑战）

（可选）问题 EC

注意： 本题为可选题目，不计分。它是为那些希望提升代码效率的人准备的额外挑战。只有在你完成了项目中所有其他问题之后，才尝试本题。

在答疑时间和项目派对上，工作人员会优先帮助有必做问题的学生。除非队列为空，否则我们不会提供关于本题的帮助。在本题中，你将实现记忆化（memoization）装饰器，通过“记住”某些计算量特别大的操作的结果来提升我们程序的效率。

请确保你已经熟悉装饰器（decorators）和记忆化（memoization）。如果你需要复习，请打开下方的下拉框获取更多信息。

Python 装饰器让你能够修改一个已存在的函数，而无需改变该函数的结构。

具体来说，装饰器函数是一个高阶函数，它……

  • 将原始函数作为输入
  • 返回一个具有修改后功能的新函数
  • 这个新函数必须包含与原始函数相同的参数

下面展示了一个装饰器的例子，它会将一个单输入函数执行两次：

>>> def do_twice(original_function):
...     def repeat(x):
...             original_function(x)
...             original_function(x)
...     return repeat

我们可以在多种场景下应用这个函数：

# Printing a value twice
>>> @do_twice
... def print_value(x):
...     print(x)
...
>>> print_value(5)
5
5
# 将同一个元素添加进列表两次
>>> lst = []
>>> @do_twice
... def add_to_list(item):
...     lst.append(item)
...
>>> add_to_list(5)
>>> lst
[5, 5]

此外，请注意，我们也可以直接调用装饰器函数，而不使用 @ 语法（即 print_value = do_twice(print_value)）。不过，将装饰器直接放在我们所修改的函数上方通常更有用，因为它们能更清楚地描述这些函数在代码中是如何被改变的。

请注意，我们在前面几题中写的 diff 函数效率很低：你可能会发现计算机会多次进行相同的递归调用。对于一个有多个参数和三次递归调用的函数，这一点可能更难以察觉。先用课堂上定义的 fib 这样的函数来观察会更直观。

注意上面这棵树的图中有多少冗余的递归调用。我们的目标是让程序把已经求值过的递归调用的结果存储起来，这样如果将来遇到相同的递归调用，就可以复用它们。例如，fib(5) 的第一个分支调用了 fib(3)，而它尚未被求值。因此我们必须遍历它后续的所有递归调用才能找到它的返回值。然而，当我们遇到作为 fib(4) 一个分支的 fib(3) 调用时，我们之前已经求出过它的返回值了！所以如果我们能以一种叫做“缓存”（cache）的方式存储并检索这些信息，就可以避免不必要的计算。我们不再需要对它的分支 fib(1) 和 fib(2) 进行任何后续的递归调用。这就是记忆化（memoization）的概念：把开销很大的计算结果存入缓存，并在我们再次执行相同操作时从缓存中取回信息。


我们将使用两个记忆化装饰器。memo 是一个通用的装饰器，它会对其所标注的函数进行记忆化。如果 memo 遇到一个它没见过的输入，它会把计算结果存入自己的cache。如果 memo 收到一个它已经见过的输入，它会直接取cache中存储的值返回，而不做任何额外的计算。我们已经为你提供了 memo 的完整实现。

你的任务是实现 memo_diff。memo_diff 是一个高阶函数，它接受一个 diff_function，并返回另一个名为 memoized 的 diff 函数；和所有 diff 函数一样，它接受 entered、source 和 limit。memoized 应当执行以下操作：

  • 当 memoized 第一次遇到一个 (entered, source) 对时，它应当使用 diff_function 计算其差异，并将该值连同所使用的 limit 一起，以一个 (value, limit) 元组对的形式缓存起来。
  • 如果 memoized 再次遇到该 (entered, source) 对，并且所给定的 limit 小于或等于缓存的 limit，它就应当返回记忆化后的 value。否则，应当重新计算差异、重新缓存并返回。

重要： 在实现这个函数时，请确保你使用元组（tuple）而不是列表（list）在缓存中存储成对的值。在字典中，键必须是不可变的（这就是为什么可以用元组，但不能用列表）。如果你好奇 memo_diff 为何与 memo 不同、以及为何这样实现，请参考下面的下拉框：

memo 和 memo_diff 有何不同？虽然 memo 只存储一次函数调用的结果，但 memo_diff 会考虑一个额外的约束 limit，它会影响缓存的结果能否被使用。当 memo_diff 函数被传入一个 (entered, source) 对调用时，它不仅仅检查这对组合之前是否出现过；它还会检查 limit 是否小于或等于缓存的 limit。这是 memo 不会执行的额外检查。

为什么 limit 要这样处理？我们已经知道，limit 表示一个 diff 函数所关心的差异上限——也就是说，超过 limit 的差异值其实可以视为相同。因此，diff 函数在差异低于 limit 时会给出准确的值，而在高于 limit 时会给出不准确的值。所以，如果一个缓存好的差异值是在更高的 limit 下计算出来的，我们就可以信任它；但在更低的 limit 下计算出来的就不能信任。

例如，下面第一次调用的结果可以让我们预测第二次调用的结果。更高的 limit 提供了更多信息。然而，第二次调用却无法让我们预测第一次调用的结果。

>>> minimum_mewtations("hello", "hasldfasdfsffsfasdf", 100)
17
>>> minimum_mewtations("hello", "hasldfasdfsffsfasdf", 2)
3

  2. 用 memo_diff 装饰 minimum_mewtations。
